01 / Computer vision · Raspberry Pi

EventLogger

A camera based presence tracker that turns sightings into an event history and sends Telegram updates when someone appears or leaves the frame.

C++23OpenCVRaspberry Pi 5Telegram
CAM 01 / LIVE
FACE MATCHED
OBSERVE
→ TRACK
→ NOTIFY

From a face in the frame to a useful event.

EventLogger runs on a Raspberry Pi with a USB webcam. OpenCV’s YuNet detects faces; SFace extracts features that are compared with enrolled photos using cosine similarity. Multiple enrollment images help recognise the same person across different camera views.

The app keeps track of who was recently seen. An absence timeout and entry cooldown turn a noisy stream of frames into a smaller set of arrival and departure events. Unknown faces trigger an alert only after a delay. These are camera based inferences, not proof that someone physically entered or left a room.

Camera processing, event handling, and Telegram polling run separately. Events are written to a local log, while Telegram subscribers can request the latest event, manage their subscription, and receive updates. Admin commands cover subscriber lists, private messages, and broadcasts.

What I learned Designing around false positives and timing matters as much as recognising a face. A useful notification needs sensible state and a clear explanation of what the camera actually observed.

02 / Hack4Good 2026 · Care technology

CareSync

A wearable communication system that helps elderly residents signal how they feel and gives caregivers a live view of those needs.

ESP32UDPDashboardML prototype

Make the first signal effortless.

CareSync starts with two ESP32 devices acting as wearables. A resident presses a button to communicate a need, such as pain, tiredness, or happiness. The signal travels over UDP to the caregiver device, where a matching LED colour gives immediate feedback.

The caregiver device forwards the event to a backend. A live dashboard collects updates so caregivers can see recent signals in one place, and a lightweight prediction pipeline explores what a resident might need next. Alert categories can be customised for different users.

The prototype reached the finals at Hack4Good 2026. The challenge was joining physical feedback, a fast transport path, and an interface a caregiver could actually monitor.

What I learned A good hardware interaction has to be legible on both ends: the person pressing the button needs confirmation, and the person responding needs context.

03 / CG2111A · Search and rescue

Alex

A teleoperated robot built to navigate a simulated lunar environment, avoid obstacles, and help locate a target.

Raspberry PiArduinoLiDARRobotics

Split the thinking from the movement.

Alex uses LiDAR to sense its surroundings and map obstacles. A Raspberry Pi handles higher level navigation and sends movement commands to an Arduino over TCP/IP with TLS. The Arduino handles the hardware work: four drive motors, encoders for motion feedback, and a robotic arm with sensor feedback.

That division kept navigation decisions separate from direct actuator control. The engineering work was in the handoff between sensing, communication, and movement: each layer had to agree on what the robot should do next.

This was a team project for CG2111A and an early chance to see how quickly real hardware exposes assumptions hidden in a software plan.

What I learned A robot is a chain of feedback loops. Navigation only works when sensing, communication, and motor control remain understandable together.
